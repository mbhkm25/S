## 2. Privilege boundary — verified, not an unrestricted security signoff

Read-only `pg_tables`/`pg_policies`/`has_table_privilege` checks confirm the named critical tables have RLS enabled. In particular, `sanad_agent_thread_participants`, `sanad_connections`, `sanad_domain_events`, and `sanad_knowledge_sources` have no direct `authenticated` SELECT privilege; the participant-aware thread/message policies and own-recipient Work Item policy exist. This **does not** prove every SECURITY DEFINER is safe or every hidden data path is tenant-safe. Before schema-dependent feature PRs, inspect the *actual* target RPC's permission checks/EXECUTE grants, query scope, response data minimization, negative and cross-tenant fixtures and Supabase advisor deltas. Never add blanket direct grants as a workaround.
