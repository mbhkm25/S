# Stage 2D.2-B — تعديل المصروف بالمحادثة والإملاء الصوتي

## النطاق والاعتماديات

فرع `stage2d/expense-chat-revision-20260927`، مبني على #418 عند `e076fec8e9e2155ffb3686c208f01facf4aac5f1`. يحافظ على فروع #413/#414/#417/#418 دون تعديل. طلب المراجعة تراكمي فوق #418؛ بعد دمج المتطلبات يُنقل base إلى main، ولا يُدمج داخل فرع الحزمة السابقة.

هذه حزمة المصروف الشخصي فقط. لا يغلق تنفيذها 2D كلها؛ تبقى الأنواع الشخصية الأخرى والمسودات التجارية. لا SQL migration جديدة، ولا مخزن مسودات جديد، ولا Bridge/ERP.

## التنفيذ

- `action_list_expense_drafts`: مسودات المصروف قيد المراجعة فقط في المحادثة الشخصية المملوكة الحالية. قراءة RLS، حد 20 نتيجة مع has_more؛ لا ادعاء بشمول القائمة عند اقتطاعها.
- `action_get_expense_draft`: قراءة المصدر والحالة والإصدار والحمولة. لا يحق للمعرّف القادم من النموذج تجاوز قيد المحادثة. يتأكد adapter من descriptor الشخصي المعتمد على الخادم ومن إتاحة عقد المصروف.
- `action_edit_personal_expense`: patch للحقول المطلوبة فقط، مبني على قراءة تمت في الدور الحالي، ثم كامل الحقول السبعة إلى `update_my_sanad_agent_action_draft_v2` الموجود. المعرف والمصدر والمرفقات والأحداث وWork Item تبقى من المسار المعتمد. يتولى SQL قفل الصف وإعادة التحقق من الملكية والعملة والتصنيف والتعارض والتكرار.
- المبلغ غير المعدل يُقرأ `payload->>amount` كنص في نفس استعلام الصف والإصدار؛ لا يمر عبر تقريب JavaScript. المبلغ المعدل نص عشري محدود، ويدعم الأرقام العربية والفارسية والفاصل العشري العربي. لا فواصل آلاف أو أسس أو تقريب صامت. [مرجع JSON النصي الرسمي](https://supabase.com/docs/guides/database/json).
- الحفاظ على الوصف والتاريخ والحساب والتصنيف ما لم يتضمن patch تغييرها. إزالة التصنيف null صريحة؛ تغيير الحساب/التصنيف يتطلب حله من أداة قراءة ناجحة في الدور الحالي. تغيير العملة يتطلب حسابًا متوافقًا؛ SQL هو الحكم النهائي.
- حالة مشتركة داخل الطلب، لكلا مساري SSE وJSON، تسمح بمحاولة تعديل واحدة فقط حتى مع نداءات نموذج متوازية. تُرفض دفعة أدوات تجمع الإنشاء والتعديل قبل تنفيذ أي منها. بعد أي محاولة لا يسمح بإنشاء مسودة بديلة أو إعادة المحاولة آليًا؛ قراءة الحالة مجددًا مسموحة. هذه ليست ضمانة توزيع عالمية لكل طلبات HTTP؛ الإصدار والقفل ومنع التكرار على الخادم يبقون حاجز الطلبات المستقلة.
- المستخدم يراجع النص الصوتي في حقل الكتابة قبل إرساله؛ الإملاء الحالي `onTranscript -> setDraft -> sendPrompt` يستخدم المحادثة نفسها. لا إرسال صوتي/اعتماد تلقائي ولا بناء منظومة صوت أخرى.
- بطاقة النتيجة الجديدة تحمل نفس action_id. قد تظهر بطاقة لهذا المعرف في أكثر من رسالة تاريخية، لكنها ليست سجلات مسودات جديدة.

## تحديث حالة الواجهة

- إشعار إبطال محلي بلا بيانات مالية أو تخزين موازٍ؛ يُعيد قراءة البطاقات بعد انتهاء أي دور (حتى الفشل/ضياع الاستجابة)، وبعد تعديل/اعتماد/إلغاء، وعند عودة التركيز للنافذة.
- الاعتماد معطل أثناء إعادة التحقق، وإجابات القراءة القديمة لا تتغلب على الأحدث. لا نمس إدخال نموذج المصروف غير المحفوظ؛ يحافظ محرره على expected_version المثبت.
- تحرير الملاحظة يثبت أيضًا الإصدار عند فتحه، فلا يكتب فوق تعديل محادثة أحدث إذا وصلت إعادة قراءة أثناء التحرير.
- تختفي رسالة «ماذا سيحدث عند الاعتماد؟» بعد انتهاء حالة review. إزالة التذييل التقني من البطاقة. نص المحادثة التاريخي لا يعاد تأليفه عند اكتمال إجراء لاحق.
- لا تضاف عبارة المراجعة القياسية مرة ثانية إذا كان الرد يشرح المراجعة وعدم التنفيذ والاعتماد من البطاقة بالفعل. يظل منع التنفيذ نابعًا من صلاحيات الأدوات، لا من صياغة النص.

## التحقق والحدود

- `npm run test:expense-chat`: 62 حالة تشغيلية مع gateways اصطناعية، تشمل المال الدقيق، ثبات الحقول، حدود القائمة، قراءة الإصدار الحالية، منع التكرار المتوازي وإعادة المحاولة بعد ضياع الرد، العقود المعروضة وإبطال القراءات. لا متصفح أو اختبار عرض UI.
- `npm run test:chat-setup`: 60 حالة PGlite + 46 عقد أدوات. يشغّل adapter فوق SQL الفعلي: تعديل نموذج ثم محادثة ثم نموذج، نفس المعرف، ورفض الإصدار السابق؛ صفر استدعاء مالي. PostgreSQL CI يضيف حالتي تنافس إعداد الحساب من المتطلبات السابقة.
- عقد المصروف السابق 56/59 حالة PGlite/PostgreSQL يبقى في CI. TypeScript/build/bundle budget وعقد كتالوج/runtime المساعد تمر قبل التسليم.
- لم يُختبر نموذج Gemini حي أو ميكروفون أو معاينة واجهة من جهة المساعد. هذه نقاط قبول المستخدم محليًا، ولا تعادلها الاختبارات الاصطناعية.

ترتيب التشغيل: اجتياز CI → مقارنة Edge الحالية بقاعدة #418 → نشر تحديث المساعد فقط → إعادة جلب الملفات ومطابقتها وفحص رفض HTTP غير المسجل → مطابقة المستخدم المحلية على 3000. قبول الواجهة والدمج ونشر Web للمستخدم. عند الحاجة للتراجع يُعاد مصدر Edge 9 من #418 مع verify_jwt=true؛ تبقى المسودات المعدلة وإصداراتها محفوظة.

## قائمة اختبار المستخدم

1. استخدم محادثة شخصية وحسابك الموجود؛ جهّز مصروف وقود 2000 YER دون اعتماده.
2. قل: «غيّر مبلغ هذه المسودة إلى 3000 وعدّل الوصف إلى وقود السيارة». يجب تحديث نفس المعرف وزيادة الإصدار، وبقاء الحساب والتاريخ والتصنيف.
3. افتح محرر المصروف وعدّل الوصف، واحفظ. ثم اطلب تغيير الوصف بالنص مرة أخرى؛ نفس المعرف والمراجعة الحالية.
4. أمْلِ «غيّر المبلغ إلى 2500» بالصوت، وراجع النص قبل إرساله. لا يحدث التعديل قبل الإرسال، ولا اعتماد مالي بعده.
5. افتح النموذج في نافذتين. احفظ في الأولى ثم حاول حفظ النسخة القديمة في الثانية: تعارض واضح، دون استبدال صامت للتعديل الأحدث.
6. مع أكثر من مسودة، اطلب تعديلًا غير محدد: يطلب المساعد تحديد المقصود عند الالتباس. الدخل/التحويل/المكتمل لا يقبلها محرر المصروف.
7. ألغِ مسودة المصروف بعد الاختبار. افحص بطاقة الحساب المكتملة: الحالة ناجحة ولا يوجد تنبيه بصيغة اعتماد مستقبلي.

لا تعتمد حركة مالية حقيقية لأغراض الاختبار.
