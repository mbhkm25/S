# SANAD Admin Control Center — Foundation

## الهدف

تشغيل لوحة إدارة سند كتطبيق ويب مستقل على `admin.sanadflow.com` مع بقائها داخل المستودع نفسه، وإعادة استخدام طبقات المصادقة وواجهات الإدارة وRPCs الحالية دون إدخال مفتاح `service_role` إلى المتصفح.

## البنية الحالية

- جذر التطبيق الإداري: `admin/`
- نقطة الدخول: `admin/src/main.tsx`
- بوابة المصادقة والصلاحية: `admin/src/AdminApp.tsx`
- غلاف مساحة العمل: `admin/src/AdminWorkspace.tsx`
- إعداد Vite مستقل: `admin/vite.config.ts`
- ناتج البناء: `dist-admin/`
- أوامر التشغيل:
  - `npm run dev:admin`
  - `npm run build:admin`
  - `npm run preview:admin`

## حدود الأمان

1. يستخدم التطبيق جلسة Supabase العادية والمفتاح العام فقط.
2. لا يُسمح بعرض مساحة العمل بعد تسجيل الدخول حتى تنجح دالة `getPlatformAdminAccess()`.
3. جميع الإجراءات الحساسة تبقى خلف RPCs الإدارية وRLS وسجل التدقيق.
4. لا يحتوي التطبيق على إنشاء حساب جديد.
5. لا يُنشر التطبيق من هذا الفرع مباشرة إلى الإنتاج.

## الأقسام الأساسية

- النظرة العامة
- المستخدمون
- مستخدمو واتساب
- العمليات
- الأنشطة التجارية
- سند Pro والمدفوعات
- إدارة المعرفة
- الإعدادات
- سجل الإدارة

قسم **إدارة المعرفة** جزء أصيل من مركز الإدارة. وهو يعيد استخدام `KnowledgeAdminSection` وواجهات المعرفة الإدارية الحالية لإدارة المصادر، إضافة المحتوى الرقمي، رفع الملفات، مراجعة الحالات، وإجراء اختبارات الاسترجاع قبل اعتماد المعرفة للمساعد.

## المرحلة المنفذة

- تثبيت بوابة صلاحية مستقلة قبل تحميل مساحة العمل.
- إضافة حالة رفض واضحة للحسابات غير الإدارية.
- إضافة تسجيل خروج فعلي من التطبيق الإداري.
- إزالة وصف `Live` المضلل إلى أن يتم تنفيذ Realtime فعليًا.
- إضافة GitHub Actions Quality Gate مخصص لبناء التطبيق الإداري.
- إضافة إدارة المعرفة مباشرة إلى شريط التنقل الإداري المستقل.
- عرض إدارة المعرفة كمساحة مستقلة دون الاعتماد على Portal أو المسار القديم داخل تطبيق المستخدم.

## المرحلة التالية

1. فصل تنقل `PlatformAdmin` عن النقر على DOM وتحويل التبويب إلى state/props مشتركة.
2. إنشاء صفحات إدارية مستقلة بدل تضمين المكوّن الكامل في كل قسم.
3. تجهيز نشر منفصل إلى جذر ويب خاص بـ `admin.sanadflow.com`.
4. إضافة `platform_events` و`platform_incidents` في migration موثق.
5. تفعيل Realtime فقط للجداول الإدارية المفلترة.
6. إضافة مركز تنبيهات وLive Activity Feed مع Push إداري.

## معيار القبول للمرحلة الأولى

- ينجح `npm run lint`.
- ينجح `npm run build:admin`.
- ينتج `dist-admin/index.html` و`dist-admin/assets/`.
- لا يستطيع مستخدم عادي الوصول إلى مساحة الإدارة حتى لو كانت لديه جلسة صالحة.
- يستطيع مدير المنصة تسجيل الخروج والعودة إلى تطبيق سند العام.
- يستطيع مدير المنصة فتح إدارة المعرفة من شريط التطبيق الإداري المستقل واستخدام المصادر والملفات والاختبار.
